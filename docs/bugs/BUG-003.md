# BUG-003 - MiniMax H3 Encoded Black Video After ComfyUI Update

## Context

The Turbo workflow saved a valid MP4 container, but every frame was black. Investigation expanded to stock MiniMax workflows because the failure was not isolated to Turbo.

## Symptoms

- Turbo output contained 247 black H.264 frames at 3456 x 1920 and 48 FPS.
- Native 4-step Turbo output was also completely black before RIFE and RTX.
- Full and pruned INT8 bases produced black or uniform gray output with the stock sampler.
- Stock 20-step controls also failed, proving the LoRA and Turbo sampler were not required to reproduce the bug.
- Healthy MiniMax videos generated on 2026-08-05 were multi-megabyte files with real pixel variation. Failed files after the update were roughly 25-160 KB.

## Root Cause

The ComfyUI core checkout had updated, but its Python packages had not been synchronized with the new `requirements.txt`. In particular, the startup log reported outdated ComfyUI frontend and AIMDO packages.

Running the portable Python dependency update installed the required package versions. After restarting ComfyUI, the user confirmed that MiniMax generated a working non-black video on the same core commit. This disproved the proposed core rollback.

## Attempted Fixes Disproved

- Removing the duplicate workflow-level SageAttention node.
- Using native resolution without RIFE or RTX.
- Using four and six Turbo steps.
- Using the full and pruned INT8 bases.
- Using stock Euler sampling at 4 and 20 steps without the LoRA.
- Forcing MiniMax attention to SDPA.
- Restoring only the changed MiniMax sampling and VAE files.

## Fix

Run `python_embeded\python.exe -s -m pip install -r ComfyUI\requirements.txt`, restart ComfyUI, and leave the server terminal open while generating.

## Tests

- FFprobe validated frame counts, resolution, FPS, duration, and streams.
- FFmpeg `signalstats` showed zero pixel variation.
- FFmpeg `blackdetect` classified complete clips as black.
- Startup logs confirmed the dependency mismatch warning disappeared after synchronization.
- The user completed a successful non-black MiniMax render after the update.
