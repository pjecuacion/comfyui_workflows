# BUG-008 - Windows clone fails on long Taomate workflow paths

## Context

[GitHub issue #1](https://github.com/pjecuacion/comfyui_workflows/issues/1) reports a successful Git download followed by a failed Windows checkout.

## Symptoms

Git reports `Filename too long` for ten Taomate anime and realism example JSON files, then `unable to checkout working tree`.

## Root Cause

The affected repository-relative paths were 172-182 characters. Their long generated suffixes pushed full paths past the legacy Windows path limit when the checkout directory was sufficiently deep.

## Fix

Renamed the ten files to short base/profile names and updated both workflow catalogs. The JSON content was not changed. The longest tracked path is now 130 characters.

## Tests

`tests/bugs/BUG-008-windows-clone-path-length.test.ps1` failed before the rename and passes afterward. It checks every tracked path against a 140-character budget, the ten expected files, JSON parsing, and both catalog references. Git identifies all ten moves as 100% identical renames.

## Lessons

Keep public workflow filenames short and stable; generated IDs belong in workflow metadata or notes, not filenames. The regression test enforces this repository-wide path budget.
