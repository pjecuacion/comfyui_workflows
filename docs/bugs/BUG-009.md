# BUG-009 - PS2 Tests workflow can't reproduce the video

## Context

A viewer (@phosfor-) on the Modern PS2 Style LoRA video asked twice for a beginner setup: they couldn't get the look
on RunningHub. The video description links `workflows/tests-h3-modern-ps2-lora/`.

## Symptoms

`video_h3_t2v_lora.json` there has the LoRA name `set-lora-by-recipe.safetensors`, a second LoRA loader at strength 0,
a 1:1 streetwear prompt from the template, 0.4 MP and a random seed. Dragged in as-is it errors, or makes a video that
looks nothing like the test.

## Root Cause

The Tests publisher exported the recipe's template (with its placeholder) instead of the values the run used. The
same placeholder is in 22 other `tests-h3-*-lora` folders.

## Fix

New bundle `workflows/beginner-h3-modern-ps2-lora/`: ComfyUI's official H3 text-to-video template + Power Lora Loader
(the proven wiring from `tests-power-lora-loader-wiring`) with the PS2 LoRA at 1.0, the scene 1 prompt, seed
20261117, 4:3 at 0.6 MP, and a plain-English guide (incl. RunningHub). The old README now points to it.
Proof run 2026-11-11 on the local RTX 5090 (E:\lora-wiring\ps2-beginner).

Not fixed here: the 22 other Tests folders and the publisher itself (follow-up, pipeline repo).

## Tests

`tests/bugs/BUG-009-ps2-beginner-workflow.test.ps1`: the beginner file has the real LoRA, trigger words, 4:3, seed
20261117, no placeholder; the old README points to it.

## Lessons

A published workflow must hold the values the video used, not the recipe's placeholders.
