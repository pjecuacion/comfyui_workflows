# BUG-010: PS2 beginner workflow opens broken on RunningHub

- **Status:** Fixed
- **Severity:** High
- **Date:** 2026-11-11

## Context
The beginner bundle `workflows/beginner-h3-modern-ps2-lora` (BUG-009 fix) was made for a viewer who uses RunningHub.

## Symptoms
Imported into RunningHub's editor (2026-11-11), the subgraph's **Power Lora Loader (rgthree)** showed
`model_weight_1 = NaN`, `lora_name_1 = [object Object]` and `null` rows. Clicking the name opened RunningHub's model
picker, not a file list. A run would skip or fail the PS2 LoRA.

## Root cause
RunningHub's "Power Lora Loader" is a different node (fixed `lora_name_1/2/3`, `model_weight_N`, `clip_weight_N`
widgets). rgthree's saved dynamic rows (`{on, lora, strength}` objects) map onto those widgets wrongly.

## Fix
Node 141 is now ComfyUI's core `LoraLoaderModelOnly` ("Load LoRA (PS2 style)"), same position and wires: MODEL in
from Load Diffusion Model (127), MODEL out to the turbo LoRA (134) and the switch (135). At strength 1.0 with no CLIP
this matches the rgthree setup. README: real RunningHub upload/import steps, no rgthree step, new troubleshooting rows.
BUG-009's test now checks the core node.

## Tests
`tests/bugs/BUG-010-ps2-beginner-core-lora.test.ps1` (fails on the rgthree file, passes now). Local render with the
core node, same seed, checked against the rgthree proof clip.

## Lessons
Workflows for beginners (and anything meant for cloud ComfyUI) should use core nodes only. Custom node packs can be
different versions, or missing, on hosted ComfyUI.
