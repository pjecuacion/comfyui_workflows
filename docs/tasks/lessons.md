# Lessons

## LESSON-001 - Workflow Repo Is Not An App Release Repo

### What Went Wrong

I applied app-development changelog/versioning habits to a public ComfyUI workflow-sharing repository.

### Why It Happened

The broad operational rulebook mentioned changelogs and versioning, but this repo does not ship a packaged app or versioned product.

### New Rule

Do not create or maintain app-style changelog files for this repo. Use git history plus lightweight docs under `docs/videos/` or `docs/tasks/` when useful.

### Correct Behavior

For a new YouTube workflow bundle, add the workflow JSON under `workflows/<video-slug>/`, add notes/prompts under `docs/videos/<video-slug>/`, and skip changelog/version files unless the user specifically asks for them.

## Working Rules

- Keep all markdown documentation under `docs/`.
- Use one workflow bundle folder per YouTube video or major experiment.
- Keep generated media and model weights out of git.
- This repo is exempt from app-style changelog and version-bump requirements.

## LESSON-002 - Validate ComfyUI Widget Serialization and Effective Media Timing

### What Went Wrong

A one-item `widgets_values` value was serialized as a JSON string. ComfyUI interpreted `a * 2` as `a`, so 2x interpolated frames were encoded at 24 FPS and doubled the clip duration.

### Why It Happened

The test validated graph links and intended frame math but did not validate the JSON array shape or inspect an actual encoded video's frame rate and duration.

### New Rules

- Preserve `widgets_values` as an array even when it contains one item.
- For frame interpolation, verify output frame count, encoded FPS, video duration, and audio duration together.
- Prefer an explicit fixed FPS when the source model FPS and interpolation multiplier are fixed.

### Correct Behavior

For MiniMax at 24 FPS with 2x RIFE, encode 587 frames at 48 FPS. The first-to-last-frame timing then matches the 294-frame source sequence.

## LESSON-003 - Validate Generated Audio Before Encoding

### What Went Wrong

I validated the Turbo graph and node registration but did not run a generated-audio finite-value check. The first real render reached `SaveVideo`, where AAC rejected NaN and infinity samples.

### Why It Happened

Graph correctness does not prove that early-checkpoint model output is numerically safe for a media encoder. The workflow connected decoded audio directly to the muxer without a safety boundary.

### New Rules

- Put a finite-value guard before encoding audio generated by experimental video/audio checkpoints.
- Test NaN, positive infinity, negative infinity, out-of-range peaks, and normal samples.
- Separate the fatal execution error from unrelated custom-node warnings in long ComfyUI logs.

### Correct Behavior

Replace invalid waveform samples, clamp them to `[-1, 1]`, preserve valid samples and sample rate, then pass the sanitized audio to `CreateVideo`.

## LESSON-004 - Validate Hypotheses With Encoded Pixels

### What Went Wrong

I initially treated duplicate SageAttention as the root cause before running a controlled no-node render. That render was still black. Several later narrow hypotheses were also disproved by real generations.

### Why It Happened

Structural graph tests and successful execution did not prove usable media. The MP4 container, frame count, and completion status were valid even though every decoded pixel was black.

### New Rules

- Treat a suspected root cause as a hypothesis until a controlled render changes the result.
- Compare against the last known working runtime commit when all model paths fail together.
- Validate real encoded pixels with signal statistics or frame inspection, not container metadata alone.
- Do not apply a checkout-wide rollback without explicit user approval.
- After a core update, synchronize `requirements.txt` before blaming the new commit; a git pull does not update portable Python packages.

### Correct Behavior

For black-video failures, test native output before post-processing, stock sampling without LoRA, known-working checkpoints, and the exact prior runtime. Record disproved hypotheses instead of presenting them as fixes.

For this incident, updating the portable Python dependencies and restarting fixed MiniMax on the current core commit. The proposed rollback was not needed.

## LESSON-005 - Account for ComfyUI Control Widgets

### What Went Wrong

The Multishot Turbo builder treated the value after `seed` as `steps`, but it was the seed widget's separate `control_after_generate` value.

### Why It Happened

The test checked an assumed numeric index instead of mapping the serialized values against every visible widget in the node.

### New Rule

When editing `widgets_values` by index, include hidden or auxiliary control widgets such as `control_after_generate`. Assert neighboring widget values independently.

### Correct Behavior

For this sampler, index 6 remains `randomize` and index 7 contains the four Turbo sampling steps.
